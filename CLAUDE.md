# indlela-api — Claude Code project instructions

Laravel 13 backend for **Indlela**, an SEO tool for agencies and SMEs in South Africa (Search Console dashboard and quick wins, site audit, rank tracking, local map pack grid, white-label reports; competitors and alerts within rank tracking). PostgreSQL database `indlela`, run locally with Laravel Sail. The SPA is the separate repo `../indlela` (React/Vite, ported from `../workforce-app`).

Auth, users, roles, login history, email templates and the audit trail are ported from `../workforce-api` (read only: never change it from here). When something exists there, port it rather than reinventing, and keep its style.

Progress (built, next, waiting on other modules) lives in `docs/PROGRESS.md` (git-ignored dev notes, kept identical in both repos), updated with every module. Routes are documented in `docs/API.md` (method, path, permission, purpose), never in README; update it with every route change.

## Architecture invariants

- **Tenancy.** A `workspace` is a tenant (an agency or an SME). Users join through `workspace_user` (one account may be in several) and act in `users.current_workspace_id`. Every authenticated route uses `['auth:sanctum', 'active', 'workspace']`; the `workspace` middleware (`SetCurrentWorkspace` → `WorkspaceContext::enter`) sets `App\Support\CurrentWorkspace` and spatie's team id, and runs before route model binding (priority list in `bootstrap/app.php`). A user in no workspace gets 403 `no_workspace`.
- **Two walls on workspace data.** Workspace-owned models (`Client`, `Site`, `EmailTemplate`, everything SEO to come) use `App\Traits\BelongsToWorkspace`: a global scope on the current workspace and `workspace_id` stamped on create, so another workspace's id 404s. Their Policies check `workspace_id` again (`Policies\Concerns\ChecksWorkspace`). New models carrying tenant data must do both, and a tenancy test (see `tests/Feature/Tenancy`) must prove A can't read or change B's rows. Outside a request (console, queue, seeders) no workspace is set and the scope doesn't filter: pass workspaces explicitly or wrap work in `CurrentWorkspace::using()`. Queued jobs must carry their workspace id.
- **Roles are per workspace** (spatie/laravel-permission with teams, `team_foreign_key = workspace_id`); permissions are global. `Role` deliberately has no global scope (spatie caches permissions with their roles across workspaces): query roles with `Role::inCurrentWorkspace()` / `inWorkspace($id)`; `{role}` and `{user}` route bindings are limited to the current workspace in `AppServiceProvider`. After changing the team id, unset a user's `roles`/`permissions` relations.
- **Default roles** come from `App\Services\Workspaces\WorkspaceProvisioner` on workspace creation (sign-up, `POST /workspaces`, `UserSeeder`): Owner (everything, always; can't be renamed, changed or deleted; a workspace keeps one active Owner — workforce's System Administrator), Manager, Analyst, Client. `RolePermissionSeeder` re-syncs the catalogue and runs `ensureDefaultRoles` for every workspace without overwriting edited roles.
- **Client access.** `roles.all_clients` decides whether members see every client of the workspace (Owner, Manager) or only those in `client_user` (Analyst, Client). Check with `$user->canAccessClient()` in Policies, scope lists with `->accessibleBy($user)` / `$user->accessibleClientIds()`. Assign clients with `UserManagementService` (its `syncClients` only touches the current workspace; never `$user->clients()->sync()`).
- Auth: Sanctum Bearer tokens. The login response is workforce's (`message, user, token, token_type, roles, permissions`) plus `workspace` and `workspaces` (`App\Support\AccountState`), so the ported FE reads it unchanged; `/me` and the workspace switch return the same without the token. Change both sides together.
- Two-step sign-in when `mfa_channel` is email/sms: `POST /login` → `{requires_mfa, challenge_token}` → `POST /login/verify-pin` → token. Only hashes of the challenge token and PIN are stored (`login_challenges`).
- Auth refusals throw `App\Exceptions\AuthFlowException` (`message`, `errors[field]`, `error_type`); the FE branches on `error_type`, so don't rename values casually. Every auth outcome goes through `LoginEventLogger` (Settings › Login history shows the workspace's members' events).
- Business numbers (lockout 5, PIN 5 min / 3 tries, reset link 60 min, invite link 72 h) live in `config/indlela.php`.
- Permissions are per page: spatie `{action}_{resource}`, actions `view|create|update|delete|approve`, resources catalogued in `App\Support\Permissions` grouped like the sidebar (the SPA's `src/config/modules.ts` mirrors the keys; keep them in step). Every action needs `view` (`Permissions::withView`). `Permissions::ADMIN_ONLY` (users, roles, login history, workspace) is Owner only. The future SEO pages are catalogued already.
- Authorise the native way: model resources get a Policy (`app/Policies/{Model}Policy.php`) combining the permission, the workspace and client access; controllers call `Gate::authorize('update', $client)`. When a FormRequest's rules query data (a name-taken check), authorise in its `authorize()` so the rules can't leak data (see `ClientRequest`, `SiteRequest`). Pages with no model use `Gate::authorize('view_settings_login_history')`.
- Settings › Roles saves a role's full permission list (`RoleController@updatePermissions`). Changes apply on the next request. Resource keys travel as values, never object keys (the FE's case transform would rewrite them).
- User administration goes through `App\Services\Users\UserManagementService`: adding an unknown email creates the account and emails a 72-hour set-password link; an existing account is just added to the workspace. Name, email, mobile, PIN channel and status belong to the account: a workspace changes them only while the account is in no other workspace. Delete = remove from the workspace (the account is soft-deleted when that was its last). It refuses disabling/removing yourself or leaving no active Owner (per-workspace advisory lock); disabling or locking signs the user out at once.
- Every model people change (not crawl/check/GSC data or sign-in bookkeeping) uses the `Auditable` trait and has a line in `App\Support\ChangeHistory::TABLES` (record type, page resource, field labels, undo rules); `ChangeHistoryTest` checks the catalogue's models are Auditable. Settings › Change history lists them with Undo (`App\Services\ChangeHistory\UndoChange`). Models use the `Auditable` trait; entries carry `workspace_id` (the record's, else the current workspace), and every History drawer reads only its workspace's `audit_logs` through `ChangeHistoryResource`. `User::auditExclude()` keeps secrets and sign-in bookkeeping out; role/client pivot changes are logged explicitly with `logAuditChange`.
- `active` middleware kills sessions of users locked/disabled after signing in.
- Transactional email = a case on `App\Mail\EmailTemplateType` + `TemplatedMail`, wording editable per workspace in `email_templates` (code defaults when a workspace has no row). User-level emails (PIN, reset) use the user's current workspace's wording. SMS via `App\Services\Sms\SmsSender` (`SMS_DRIVER=log|twilio`).
- Files go on the default `s3` disk (the S3-compatible `minio` Sail service locally; real S3 later). Jobs run on Redis under Horizon.
- Every migration needs a working `down()`. Unique indexes on soft-deleted tables are partial (`WHERE deleted_at IS NULL`) and per workspace.
- **Search Console.** One `google_connections` row per workspace (tokens `encrypted` casts, never serialised); OAuth via Laravel's Http client (`Services/SearchConsole/GoogleOAuth`, no google/apiclient). `/google/callback` is public: who/where come from the encrypted, single-use, 10-minute `state`. `GoogleConnectionService::accessToken()` refreshes; `invalid_grant` marks the connection `error` and answers 409 `google_not_connected`. Google calls go through the `SearchConsoleApi` interface (tests: `Http::fake`). Data: `gsc_daily_totals` (accurate totals) and `gsc_query_page_daily` (query × page × day, md5 hash columns for uniqueness), both upserted so re-syncs are idempotent; unlinking or relinking another property deletes a site's rows. `SyncSearchConsole` carries site + workspace ids, runs in `CurrentWorkspace::using()`, is unique per site and runs on the `redis-long` connection (retry_after 1900 s > job timeout 1800 s; Horizon `supervisor-long`). Reports (`SearchConsoleReports`) are single GROUP BY queries paginated in SQL, built from the models so the workspace scope applies; thresholds and the expected-CTR curve live in `config/indlela.php` `search_console`. Site sync bookkeeping columns are excluded from the audit trail (linking a property is audited).
- **Site audit.** `RunSiteAudit` (audit + workspace ids, `CurrentWorkspace::using()`, unique per site, redis-long, 2 tries, failed() marks the audit failed) → `SiteCrawler` (network: pages, redirect chains, links, link status checks) → `AuditAnalyser` (database only: inlinks, issues, health score, comparison; safe to re-run) → `RunAuditVitals` → `VitalsRunner` (PageSpeed Insights, never fails the audit). Pages are fetched through the `PageFetcher` interface: `HttpPageFetcher` gets raw HTML with Laravel's Http pool (no JavaScript); a Browsershot renderer can be bound instead later for JS-built sites. Tests drive the real fetcher with `Http::fake` (`tests/Support/SiteAuditHelpers`). Issue types, severities and their wording live in `App\Support\AuditIssues` (code), thresholds in `config/indlela.php` `audit`. `site_audits` and `site_audit_issues` use `BelongsToWorkspace` (+ `SiteAuditPolicy`); pages, links and vitals carry no workspace and are only reached through their audit (`{page}` is a scoped binding). Cancel = status `cancelled`, checked by the crawler between batches. One running audit per site (cache lock + 409 `audit_running`). Permissions: `view_site_audit`, `update_site_audit` (run, cancel, settings). `site-audit:run-scheduled` daily 02:00 also prunes all but the latest 10 audits' detail rows per site.
- **Rank tracking.** DataForSEO SERP API through the `SerpApi` interface (`DataForSeoSerpApi`, Laravel Http, Basic auth from `services.dataforseo`; `DATAFORSEO_SANDBOX` picks the free sandbox host; tests `Http::fake` via `tests/Support/RankTrackingHelpers`). Every DataForSEO answer is an envelope (`status_code` 20000) with per-task codes; `DataForSeoException::$retryable` separates rate limits/5xx/timeouts from permanent refusals. No credentials → 409 `rank_checks_paused`, scheduled commands skip. **DataForSEO is one platform account: never expose platform cost, balance, credentials or the provider's name to workspaces** (responses, messages, error text; `rank_checks.cost` is stored for an internal view only; `DataForSeoException` renders a neutral 502). Beta limits (`RankLimits`, `RankSpend`): active keywords per workspace (`workspace_keyword_limit`, `workspaces.rank_keyword_limit` override; 422 on add/reactivate under a per-workspace advisory lock), check-now a SAST day (`check_now_daily_limit`, counted in `rank_checks.live_requests` per request, 429 `check_limit_reached`), platform monthly spend cap (`monthly_spend_cap_usd`, all workspaces; `PostRankTasks` claims only what fits under a platform advisory lock and fails the rest "Skipped: rank checks paused"; check-now 409 `rank_checks_paused`). Usage = `{keywords_tracked, keyword_limit, checks_now_today, check_now_limit, paused}`. `rank_keywords` (keyword × location × device, daily/weekly, weekly by default; `location_key` + partial unique index; soft deletes) and `rank_checks` (unique per keyword and day: never two paid checks a day; a live "check now" reuses the row) use `BelongsToWorkspace` (+ `RankKeywordPolicy`; site routes via `SitePolicy::viewRankTracking/manageRankTracking`); `rank_locations` is global reference data. `rank-tracking:post-checks` (01:00) → `PostRankTasks` (one per workspace and 100 checks, unique per batch, claims rows with `UPDATE … RETURNING` before posting) → `rank-tracking:collect` (5 min: fails checks pending > 24 h, `CollectRankResults` → `FetchRankResult` per task, unique per check+task) and `CheckKeywordNow` (live, unique per keyword+click, no retries: each call is billed); all on the default `redis` connection, carrying their workspace and running in `CurrentWorkspace::using()`. `SerpParser` (pure) reads a SERP; `RankKeywordQuery` (lateral joins: latest/previous/7d/30d done checks) feeds every list and report in `RankReports`; change = then − now (positive = up, not ranking = 101). Prices, depth, limits in `config/indlela.php` `rank_tracking`. Permissions `view_rank_tracking` / `update_rank_tracking`. **Competitors** live inside rank tracking (same permissions, `SitePolicy` / `SiteCompetitorPolicy`) and cost nothing extra: `SerpParser` also returns `organic_domains` (hosts by position) stored on each check; `RankChecker::complete` → `CompetitorTracker::record` writes `rank_competitor_positions` for the site's active competitors and `competitor_alerts` for key keywords (`rank_keywords.is_key`); a competitor added/restored/resumed is backfilled by `BackfillCompetitorPositions` (90 days). `site_competitors` (Auditable, ≤ 5 active per site under a per-site advisory lock) and `site_competitor_settings` (alert recipients, Auditable) are in `ChangeHistory`. `CompetitorReports` (SoV, weekly trend, head-to-head, suggestions) is grouped SQL over each active keyword's latest done check. `rank-tracking:competitor-alerts` (07:30 SAST) sends the `competitor_alert` template per site.
- **Local grid.** Google Maps rankings from a size × size grid of points (3/5/7, 0.5–5 km) around a centre for one Maps listing, through the same DataForSEO account (`SerpApi::mapsLive`: one live/advanced request per point via `Http::pool`, no retries; never the provider, cost or money in responses: `LocalGridException` messages are neutral). `map_grids` (Auditable, in `ChangeHistory`, `business_*` fixed after create, `business_key` + partial unique per site × keyword × business × centre, soft deletes) and `map_grid_scans` (frozen settings, metrics arp/atrp/solv/found_pct, `scanned_on` = SAST day) use `BelongsToWorkspace` (+ `MapGridPolicy`; site routes via `SitePolicy::viewLocalGrid/createLocalGrid/manageLocalGrid`); `map_grid_points` (no workspace, reached through the scan) and `map_grid_searches` (ledger of business searches) are data, not audited. `GridGeometry` / `MapsParser` are pure (unit-tested). `GridScanner::start` creates the scan and all points pending inside `RankSpend::serialised` only if the whole scan fits under `rank_tracking.monthly_spend_cap_usd` (grid points and searches are part of `RankSpend::breakdown`); `RunMapGridScan` (scan + workspace ids, `CurrentWorkspace::using()`, `ShouldBeUniqueUntilProcessing` per scan, 1 try, default `redis`) checks one round of `concurrency` points and re-dispatches itself; the last round finishes the scan. `GridLimits`: active grids per workspace (422), manual scans and business searches a SAST day (429), each under a per-workspace advisory lock. `local-grid:run-scheduled` (03:30) fails stale scans and queues due weekly/monthly grids. Permissions `*_local_grid` (create = add + business search, update = change/pause/scan now, delete). Numbers in `config/indlela.php` `local_grid`.
- **White-label reports.** **Client-facing output never shows Indlela**: the report PDF (`resources/views/reports/pdf.blade.php`), the share page's data (`/public/reports/{token}`), and the `client_report` email (`ClientReportMail`: own layout `emails/client-report`, From name = the workspace, Reply-To = the agency person, no `app_name` variable) carry only the workspace's name, logo and `brand_color`. **Reports are frozen snapshots**: `ReportSnapshot` reads the data once at generation into `reports.data` (no ids, emails or storage paths besides `branding.logo`, which responses replace with a served `logo_url`), and the PDF, in-app view, share page and email all render that; never re-query live data for an existing report. `GenerateReport` (report + workspace ids, `CurrentWorkspace::using()`, unique per report id, `redis-long`, 1 try) writes the PDF at `reports/{workspace_id}/{id}.pdf` inside the transaction that marks it ready (put `false` → failed, no phantom). Share tokens: 40 random chars, rotated on every share, 404 with one body for unknown/revoked/expired, `X-Robots-Tag: noindex`. `reports:run-scheduled` (hourly; each schedule has its own `send_hour`, SAST) claims each schedule with a conditional UPDATE once a month. `reports` / `report_schedules` use `BelongsToWorkspace` (+ `ReportPolicy`; site routes via `SitePolicy::viewReports/createReports`). Permissions `view_reports`, `create_reports` (generate, send, share, schedule), `delete_reports`. Summary wording rules in `ReportSummary` (unit-tested).
- **Platform workspace.** `config('indlela.platform_workspace')` (`INDLELA_PLATFORM_WORKSPACE`, a slug; empty = off) names the Indlela staff workspace (`App\Support\PlatformWorkspace`). Platform permissions (`Permissions::PLATFORM_ONLY`, today `view_platform_usage`) exist **only there**: Owner's sync and the seeded Superuser role there; everywhere else `Permissions::forWorkspace` / `grantableIn` / `groupsFor` leave them out (Owner sync, Roles grid, `RolePermissionsRequest`), `AccountState` filters them from `permissions`, and `WorkspaceProvisioner` revokes them from any role. **Cross-workspace queries live only in `App\Services\Platform\PlatformUsage`** behind the `view-platform-usage` gate (current workspace is the platform one AND the permission): no other endpoint returns figures from other workspaces (RankSpend's platform total only drives the cap and `paused`).
- Paginated lists default to **15 per page** (`per_page` 10–100). List pages get `DELETE /x/{id}` and `POST /x/bulk {action, ids}` through the `Controllers\Concerns\SettingsList` trait (`sortList`, `bulkActive` with a 409 hook for rows in use, `historyOf`), changing each row through its model so every change is audited.

## Commands

```bash
./vendor/bin/sail up -d                                   # pgsql, redis, mailpit, minio (RustFS), app on APP_PORT
./vendor/bin/sail artisan migrate --seed                  # catalogue, first Owner + workspace (SEED_* in .env)
./vendor/bin/sail artisan storage:bucket                  # once: create the AWS_BUCKET bucket
./vendor/bin/sail artisan horizon                         # queue worker; dashboard http://localhost:8000/horizon
./vendor/bin/sail artisan test                            # phpunit against Postgres indlela_testing
php artisan db:seed --class=GscDemoSeeder                 # demo Search Console data (first workspace, demo.indlela.local)
php artisan db:seed --class=AuditDemoSeeder               # demo site audits for the same site (no crawling)
php artisan db:seed --class=RankDemoSeeder                # demo rank tracking for the same site (60 keywords, 90 days)
php artisan db:seed --class=CompetitorDemoSeeder          # demo competitors, positions and alerts on top of it (idempotent)
php artisan db:seed --class=LocalGridDemoSeeder           # demo 5x5 local grid with two scans for the same site (idempotent)
php artisan db:seed --class=ReportDemoSeeder              # a real white-label report (PDF + share link) of the same site
php artisan schedule:work                                 # scheduler locally (rank checks 01:00, collection every 5 min, local grid 03:30, audits, GSC, monthly reports hourly at each schedule's hour)
./vendor/bin/sail bin pint                                # code style
```

Without Docker for PHP (local PHP 8.3+ with pdo_pgsql, Sail's pgsql still running): `DB_HOST=127.0.0.1 DB_PORT=5433 php artisan test` (the port is FORWARD_DB_PORT). `tests/TestCase.php` refuses to run against anything that isn't a local test database. Run the tests before claiming done.

## Conventions

Commits imperative, ≤ 72 chars, Conventional-Commit prefix, body says why. One concern per PR, ~15 files max; body sections `## Summary`, `## Decisions baked in`, `## Files`, `## What is NOT in this PR`, `## Test plan`.
